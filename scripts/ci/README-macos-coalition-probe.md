# macOS coalition capability probe

> **Doc status:** Reference

`probe-macos-launch-coalition.py --output <report.json>` tests ordinary-user API access, two uniquely labelled temporary user launchd jobs, an independently launched outsider, held guardian leases, guardian-only counter baselines and resource-coalition isolation. It requires macOS and refuses root. Nonzero exit2 means unsupported runtime/API/domain; exit1 means a failed invariant or fixture cleanup. Every controller run writes a structured result. There is no privileged setup or automatic fallback.

This first phase does **not** test descendants, detached children, guardian-loss game survival, production tracking, account recovery or packaged acceptance. `family_recovery_acceptance` remains false even if the phase passes. A source build or successful job cannot close those gates.

Readiness records must be JSON objects bound to the expected nonce, with unsigned 64-bit integer coalition/counter fields, a nonreserved coalition ID and consistent started/exited/active counters. Malformed records fail the fixture with a bounded reason and a structured controller report. API-unavailable records remain unavailable; their diagnostic payload is not echoed. A valid record still requires an actually held guardian lease. Sixteen mocked controller/readiness tests exercise these controls; they do not qualify native lock or macOS API behavior.

`python3 scripts/ci/test_macos_launch_coalition_probe.py` checks controller safety with simulated command faults: a bootstrap error/timeout must unload the exact attempted label, a still-loaded job after bootout must fail, rejected bootstrap with a confirmed absent job retains its unsupported result, shared outside coalitions cannot pass, and root cannot qualify ordinary-user behavior. These tests do not execute or qualify macOS APIs.

The ABI probe is constrained by pinned Apple XNU source `f6217f891ac0bb64f3d375211650a4c1ff8ca1ea`: [coalition overview](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/doc/observability/coalitions.md), [counter prefix and bounded copy](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/sys_coalition.c#L252), and [process-query structure/flavor](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/sys/proc_info_private.h#L63). Source declarations do not establish runtime availability; the executable probe checks actual symbols and return sizes.

Only disposable synthetic Python guardians run. Temporary jobs never enter login/autostart directories; cleanup addresses their exact unique labels. No user game, credential, server connection, kernel setting, signing entitlement, system service or production installation is used. The installed platform's launchd behavior still requires the later game-survival controls.

Completed bootstrap commands retain their exit code and bounded stdout/stderr with host paths redacted. Diagnostic text is data: the fixture still refuses root and does not automatically retry, elevate or switch domains.

For focused investigation, dispatch the existing desktop-build.yml workflow on the review branch with probe_only=true and no release_tag. Only the macOS probe runs; installer checks/builds/release are excluded for this explicit manual mode. Normal push/PR/tag and default manual runs retain their checks. Actual job selection must be observed before claiming the targeted path works.

An explicitly recorded fixture-only review iteration may use a skip-CI commit and this manual probe to preserve an already running baseline. That does not satisfy required PR checks on the new head or authorize merging/releasing; the final source must pass normal required CI and all original acceptance gates. See [GitHub skip behavior](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs) and [branch-specific manual runs](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow).

The controller accepts an explicit --domain user or --domain gui for the caller's own UID only; user remains the default. System domains, other-user selectors and root execution are rejected. For a targeted manual GUI experiment, select probe_only=true and probe_domain=gui. It first records a same-runner user-domain control (success or the known unsupported exit2 are recorded; invariant/cleanup failures stop the job), then requires the selected GUI probe to pass normally. Normal events still select user. This is an explicit experiment, not automatic fallback or production architecture selection; both structured results are retained.

The separate `probe-macos-coalition-family.py --output <report.json>` candidate extends the synthetic experiment to fast wrapper→middle→leaf exits, normal and new-session descendants, simultaneous independent families, self-crash, fresh job isolation, and normal/detached leaf survival after an exact-label guardian kill. Its private temporary directory contains only predefined nonce-bound UUID cases. Unbound requests are rejected; an injected inspection failure must remain unavailable. Held leaf leases use raw non-inherited descriptors kept until kernel exit; survival also requires a later heartbeat after the guardian lease retires. Cleanup stops registered cases before unloading exact labels, with bounded role lifetimes if the controller disappears.

Dispatch this experiment only with `probe_only=true`, `probe_domain=gui` and `probe_family=true`. The family option defaults false and invalid selection fails before native probing. The selected API probe and family probe propagate failure normally; all reports share the existing artifact prefix. Thirteen mocked family controls supplement the sixteen baseline controls; local checks do not qualify native descendants. Even a native `fixture_family_lifetime_passed=true` keeps `family_recovery_acceptance=false`: production integration, exact account/ACL recovery, packaged restart/install/update/rollback and other Mac runtimes remain separate. Metadata-substitution controls do not demonstrate actual PID recycling; external launcher/service handoffs remain unknown.

Only the deliberate API-injection recovery window may wait for an unavailable snapshot to be replaced, and only while the same guardian lease remains held. It requires a fresh valid same-coalition counter snapshot within the existing bound. Dead guardians and ordinary inspection failures remain unavailable; no end-of-game or fallback result is inferred.
