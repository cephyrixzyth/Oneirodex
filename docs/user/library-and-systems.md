## Game Catalog

Route: `/library`

- Dense cover grid with filters (platform, status, freshness, etc.).
- **One tile per title, not per copy.** A title you hold on several systems is a single tile. The platform chip names **the latest system it was released on** and counts the rest: a game on NES, GBA and SNES reads `GBA +2`. Filtered to a system, the chip names *that* system instead — the same game under the NES filter reads `NES +2`, because that is the copy you are looking at. The other copies are reachable from the tile's **Preview → Available on**, with a launcher per emulator core; they are not separate tiles. Titles pair on their normalised name, because `igdb_id` and `slug` are unique per row and so cannot be shared across systems. Page counts count titles, so pages stay full.
- **Type-to-search:** a **Search by title** field sits in the Filters popover. Results update as you type (debounced ~300ms) via browse `name=` (alias `q=`; case-insensitive substring) — no separate Search submit. Empty / whitespace query clears the title filter. Same params on `GET /api/favorites`. **Ctrl+K** opens the command palette: two letters search titles from any page; an empty box lists recent titles and household favourites.
- **Saved filters, and filters that can say "or":** the Signals chips can only ever mean *and* — tick three and you get titles matching all three. Under them, **Build a filter** opens a small builder where rows sit in groups that read **All of** / **Any of** / **None of**, and groups can nest. That is how you ask for something like *plays in VR and is behind, or anything added recently*, which no number of chips can express. It tells you how many titles match as you build, and **Save** keeps it under a name — your own, not the household’s — so it comes back as a button next time. Applying one does **not** clear the chips: a filter you built and a chip you then tap both apply, because that is what tapping the chip meant. If a row is wrong the builder marks that row rather than saying the whole filter is invalid. Tick **Show on Collections** when you save and it also appears as a shelf on the **Collections** page — a *smart* shelf, answered by the question rather than filled by hand, so it keeps up as the library grows. Opening one is just the catalog with that filter already applied.
- **Multi-select:** checkbox (**bottom-right** of a tile, above the badges there), **long-press**, or **Shift+click** range → sticky bar with **Select page** (all visible tiles) · Favorite / Unfavorite · **Add to wishlist** · **Play status** (Unplayed / Unfinished / Beaten / Completed / Won't play / Clear) · Refresh freshness / **Refresh covers** (More; librarian+ · max 20) · Clear · count; batch toasts report `updated`/`queued` / `skipped` / `failed`. **Esc** clears selection. Missing batch routes disable with a title.
- **Page size** (items per page) allowlist: **20 / 50 / 100 / 200 / 250 / 300 / 400 / 500 / 1000** — set in Preferences; browse API rejects other values.
- **Show titles under tiles** lives in **Preferences → Look & density**, directly under the tile-size slider. It toggles a one-line title strip under each cover (Tile view; Rows already names every entry). On by default, because box art alone is a weak identifier across a ROM set where a whole series can share one piece of art — switch it off for a plain art wall. The grid's row height and the Discover shelf height both follow it. It used to be a labelled checkbox on the top bar, which spent permanent bar width on a setting you change once.
- Tile size comes from your preferences (percent slider in the top bar) and animates smoothly on the grid. The slider is **collapsed to a single dot** — the slider's own thumb, in your theme's accent colour — until you hover it or tab to it, then opens; the title count reads immediately **before** it, so the number comes first and the control that changes it sits beside it. Tile chrome — corner controls, **Play**, badges, platform chip, the Preview pill — is sized **from the tile** (`--od-tile-*`), so it scales with the slider instead of staying one fixed size.
- **Tile / Rows / Grid** in the top bar (next to All / Games / Soft titles / …) changes how the catalog is laid out. **Tile** is the cover grid. **Rows** is a Steam-like title list (cover, name, system and year) whose row height follows the tile-size slider. **Grid** is Steam-like genre shelves (horizontal tracks grouped by primary genre — arrows and a slider under the covers, tighter than Discover so many genres fit; genre headings stay in the content gutter and are not clipped by Tile hover-pad). The choice is remembered in this browser (`gt.library.layout`). **Favorites** uses the same switcher. The tile-size slider (0–100%, about 110–300px) applies at full size to Tile, Rows, and Grid (and Discover). The default 50% is roughly six covers across a desktop content width — it used to be 260px and about four, which is a lot of scrolling for a library in the thousands.
- **Grid and Discover take arrow keys and a controller D-pad.** The whole shelf stack is a single tab stop, so Tab reaches the covers and Tab again leaves them — it no longer walks every tile on every shelf. Left/Right move along a shelf, Up/Down move between shelves, Home/End go to the ends of the current shelf and Ctrl+Home / Ctrl+End to the first and last cover in the stack. Moving down into a short shelf lands on its last cover but remembers the column you asked for, so continuing down into a longer shelf returns you to it rather than stranding you at the left edge. Arrows only move: Enter opens a title, Space toggles its selection. Each move scrolls by the least amount needed to reveal the cover, and follows OS reduced-motion.
- **One tile menu at a time** — opening a menu on another tile closes the first, rather than leaving two on screen.
- **Tile controls** (favourite · play status · menu, top to bottom) appear **on hover**. A favourited title keeps its heart visible with the pointer elsewhere, so you can see what you have favourited while scanning. Touch devices show all three, since there is no hover to reveal them.
- Hovering a tile **grows it 25% equally around its resting box** — scale only, no accent glow. Covers have **no outline at rest**. While hovered or keyboard-focused, a **tight** accent outline sits on the tile edge (no gap). With OS reduced-motion on you still get the size change; only the animated travel is suppressed. The enlarged tile paints **over** its neighbours (and their badges), not under them. First-row enlarge still has a short inset under the thin top bar; left and right it **overlaps** the gutter rather than growing inward or clipping. Opening the tile's menu or its play-status dropdown does not shrink the tile: the panel divides the scale out for itself, so it reads at its true size while the tile you are still pointing at stays enlarged.
- When a title has trailer video, hover (and keyboard focus) also plays a **muted** preview over the cover — the cover stays the identity; this is a preview, not playback, and it never plays with sound. With OS reduced-motion on, the cover stays and nothing autoplays.
- **Tile menu**: themed, every row the same shape, with **Add to collection…** (pick a shelf without leaving the grid) and **Report an issue** at the bottom (it opens the report form already filled in with the title). There is no "Play demo" item — Oneirodex ships no demo feature. The menu stays true size over the grid while the tile remains enlarged.
- **A greyed-out Play** is now a button, not a dead label. Press it and it says why browser play is unavailable for that title (missing firmware, unsupported archive) and offers **Browser play requirements**, **Report an issue**, and — for admins — **Emulator profiles**. The reason used to live only in a mouse-over tooltip, which never appeared on a touch screen.
- **Pagination**: per-page on the left, First/Previous/Next/Last as a row of words in the middle (no segmented box), page indicator (`Page 3 of 12`) on the right. The bar sits at the **foot of the library grid** — it does not follow you while you scroll, and it has no glass surface or outline of its own. Per-page is a plain select, not a glass dropdown. On a long page, Next is below the tiles.
- A cover that downloads badly can no longer distort its row — tiles are pinned to 3:4 and crop the overflow.
- **Blank downloaded covers** (1×1 stubs, near-solid washes) are replaced with the same titled decade-room art used when nothing local exists, so a CDN 200 cannot leave a hole in the grid. Screenshots and other kinds are left alone.
- **Preview** sits in the middle of a tile on hover: a larger popup with the cover, blurb, **Released** and **Added** dates side by side, the Discover **reason** when the tile came from a shelf (“Because you played…”), extra **tags** (modes / themes when metadata has them), **household friends** who played or favourited a copy (share-activity gated — not a store crowd), and **Steam / GOG / Epic / catalog / YouTube marks** when the title has them (GOG / Epic from the same editions request as Available on). Browse also sends one `trailer_embed_url` when the title has trailer video, used for the muted tile-hover preview — not a second player. The YouTube mark in Preview is a link out. At the bottom, **Available on** — every system in your libraries that holds this title, with a **Play** button per emulator core for each. Copies that cannot be launched are still listed, with the reason (missing firmware, catalog-only, no browser core). Backed by `GET /api/games/<uuid>/editions`, ACL-scoped like browse; titles are paired by name because `igdb_id` and `slug` are unique per row and so cannot be shared across systems.
- **Covers with no art** are drawn rather than fetched: a panel in the **active decade-room theme** (wood den, teen bedroom, carpet den, media centre, arcade, desk), the Oneirodex mark in your accent colour, and the game's title as real text — legible at any tile size, unlike the old baked-in placeholder image. Admins can also apply decade-room stock packs from Art Studio.
- **Filters** in the two-bar chrome open from a **Filters** button beside the rail toggle at the left of the top bar — open the nav, narrow the list. Neither control has a resting outline; they are not one shared box. The view switcher in the middle of the bar is centred on the **grid**, not on the window, so it lines up with the tiles under it. The panel opens **downward and to the right** from that button, so it never sits over the rail or runs off the left edge when the rail is collapsed. It scrolls only when the window genuinely cannot fit the whole list — on a tall screen every filter is visible at once. The panel is one box — no separate popover header repeating the word "Filters" — and **Apply · Clear · Done** lead it as a single merged control, pinned to the top so they stay reachable while a long filter list scrolls under them.
- Title-card chrome (UID-001): **four-corner** placement — **favorite** + **play status** + **menu** stack **top-right** (hover-reveal; a favourited heart persists) · the **select** checkbox sits **bottom-right above the badges** there (it used to be a fourth button in the top-right stack, where it appeared on every tile the moment one was selected and read as a glitch) · transitional badges (UPDATE / MISSING / NEW / VR / …) **top-left** (no overlap with favorite) · platform chip **bottom-left** when present · kind / LANG / OWNED etc. prefer remaining corners. Corner controls reveal on hover; on touch, where there is no hover, they rest visible. All badges share one height, padding and font size. **PLAY** sits under the top-left badge stack when both are present (badges win top-left). **Occupied corners only** — no empty reserved slots. **Rounded-square** chrome on badges, +N overflow, platform chip, hamburger, favorite, and status. Post-deploy: rebuild member SPA dist **and** **Reset Themes** (theme volume CSS copies of badge chrome).
- **VR** is a tile badge in the same top-left stack (not dismissable). It is **not** a Library filter chip — use **More → VR** for the VR catalog.
- **MISSING** (not dismissable) means browse marked the title removed from disk (`path_status=missing` / `path_missing`). Tooltip: files are no longer on disk.
- Title-card badges may also show NEW / UPDATE / **LANG** / **PATCH** when signals exist, plus **EXP** / **EMU** / **TOOL** when the title is cataloged as Soft title / Emulator / Utility (gaming software — not a main-game match; API tokens `experience`|`emulator`|`tool`). Details shows the same kind as a chip. **No OUT / ~ / RELEASE** on tiles (UID-001); RELEASE LHN chip retired; UPDATE alone covers freshness-behind.
- **Signals** chips live **inside** the filter section (UPDATE · MISSING · NEW · LANG) and toggle the same browse params (`has_updates`, `path_missing`, `new_import`, `needs_translation`); they persist with other library filters. Legacy URL params `freshness_behind` / `recent_release` / `is_vr=1` still parse when present but have no chip. If the API does not filter `path_missing` yet, the Library page still filters the loaded page client-side.
- Watch/scan may toast “N games added to Library …” (top-right); the same row lands in **Notifications**. More than five toasts at once collapse to **N notifications**.
- **Kind** views on the catalog bar (All · Games · Soft titles · Emulators · Utilities) pick one `item_kind=` at a time (All omits the param). Persist with other library filters. Favorites list accepts the same API param. API/DB tokens stay `experience` / `tool`.
- **Multi-select bulk** (Waves 9–12): `POST /api/games/batch/favorite` (`uuids` ≤100, `favorite` true|false) · `POST /api/games/batch/status` (`uuids` ≤100, `status` unplayed|unfinished|beaten|completed|'' to clear) · `POST /api/games/batch/wishlist` (`uuids` ≤50; title from `Game.name`; requires request permission; skips pending dupes) · `POST /api/games/batch/freshness/check` (`uuids` ≤50; API still accepts `only_stale`) · `POST /api/games/batch/refresh_images` (`uuids` ≤20; librarian+; 202 `{ queued, skipped, errors }`) — ACL-scoped, partial success. Sticky bar wires favorite · wishlist · play status · freshness · covers (More); missing routes disable with a title. **Refresh freshness** from the sticky bar **always re-probes** the selection (Wave 10). Partial-success toasts surface `updated`/`queued` / `skipped` / `failed`. Not a DRM download queue; admin library-wide refresh remains `POST /api/admin/freshness/refresh`.
- **Ctrl+K** searches **library titles** from any page once two characters are typed (Search library group). An empty palette shows recent titles and household favourites. Navigate / More / Account stay listed.
- **LANG** filter uses your Preferences → Preferred game language (default `en-US`) and only includes titles whose ROM language is known and mismatched — see [translation-patches.md](translation-patches.md). Console ROM peel (**BE-DET-4**) persists path/tag `rom_region` / `rom_languages` when known so LANG honesty has something to compare against after scan/identify (not a Class A catalog). Peel covers cart + disc/late leaves (incl. Saturn / Dreamcast / Neo Geo CD · `.gdi`/`.cdi`) when those libraries are scanned — threshold stays high.
- **Multi-disc sets (BE-DET-5):** scan/identify can collapse `(Disc|Disk|CD N)` siblings into one Library title with disc extras; browse/details expose `is_multi_disc` and `discs[]`. Game **details** shows disc chips (count + Disc N). Tiles stay at the UID-001 badge cap — no disc chip on the grid.
- Platform skins tint chrome when you are focused on a single system.

## Systems hub

Route: `/systems`

Browse-by-console hub (Style **B+C**):

- Platforms are grouped by family (Nintendo, Sony, Xbox, Sega, PC & Other, Retro & Classic).
- Family skins include **Switch** and **Wii U** under Nintendo, **PSP** under Sony, **Sega Pico** under Sega, and **Neo Geo AES** / **Arcade** / **CD-i** / **Jaguar CD** / **GX4000** under Retro & Classic (same leaf enums as create-library). **Amiga** / **Amiga CD32** / **MSX** / **ZX Spectrum** / **Amstrad CPC** / **Atari ST** / **Apple II** / **Atari 8-bit** / **X68000** / **PC-98** / **BBC Micro** stay with PC. **Game & Watch** is Nintendo (handheld). Unknown ids still fall under PC & Other.
- Each tile shows a **per-system** mark (themed AI art when generated for your active theme under `static/library/system-marks/…`, otherwise the SVG motif), game count, and a **Browser** / **Companion** / **Catalog** play-mode badge. Switch / Wii U / Arcade / Neo Geo AES stay **Catalog** (no fake browser Play).
- Opens Library filtered to that platform (`/api/library_platforms` includes `play_mode`).
- **Ways to Play** (`/ways-to-play`, More → Play) is the same honesty as a page: Browser / Companion / Catalog catalog filters, plus Systems and VR when enabled. Not a store “verified” badge. Game Catalog Filters also have a **Play path** select (`play_mode=`).
- Empty groups mean no Library leaves for that family yet — Sony, Sega, … do not show tiles until Ops creates those leaves. Switch only appears after a `SWITCH` leaf exists. A leaf with **0 games** still shows a tile (count fills when dumps land and a scan runs).
- **Help** and **Trailers** in More follow Admin → Server Settings on this page the same as Discover. They are not Systems-specific.
- **Set completeness** (optional): after an admin uploads a No-Intro / Redump / TOSEC / MAME DAT, tiles show `owned / total · percent` for a region and link to `/systems/completion` for the missing list. Matching prefers file CRC/MD5/SHA1 when hashed, else titles; each game counts once (clone dumps and other-region variants fold onto the preferred entry). Regions include USA / Europe / Japan plus Brazil, Korea, Australia, UK, France, Germany, Spain, China, World, and Other. Under the two-bar chrome, the platform/region identity, owned count, **Systems** / **Browse library** / **Licensed catalog**, and the region filter live in the top bar. See [reference-sets.md](../runbooks/reference-sets.md).
- **Licensed catalog** (`/systems/catalog`, **Catalog** on a console tile): IGDB regional release counts for that system (main games only). Empty cache means an admin has not refreshed it yet — not “zero games ever made,” and not Wikipedia. Windows / DOS / Mac libraries are omitted. France / Germany / Spain / UK rows are DAT regions; IGDB does not have those as release-date countries.
- **Export packs** (a boxed note beside the page intro, top right): download **ES-DE** `gamelist.xml` (`/api/export/esde`) or **Pegasus** metadata (`/api/export/pegasus`) for external frontends. Optional; you do not need them to browse Systems. Paths are portable (`<library>/…` under configured roots, else basename) — server home/NAS mounts are not leaked. Admins also find the same downloads under Integrations → Export packs.

Play matrix: [browser-play.md](browser-play.md).

## Discover & more

- **Discover** (`/discover`) — storefront shelves: **Curated for you** (unplayed titles in genres you already favourite), **Latest Games** (newest *releases*), **New Library Games** (newest titles added *here*), **Upcoming** (what is releasing soon on your systems that the library does not hold yet, plus anything on your wishlist that is still ahead — with the date on the tile), **Extras not on the vault** (sidecars for titles you play or favourite that are missing on disk — never a sale row), plus whatever shelves your admin has arranged. Some shelves are **timed events** and appear only during their run. Above the shelves, **Surprise me** picks one title from the top of your own taste ranking — press **Another** for a different one, or tap one of your genres to steer it. It never offers anything you have favourited, played or marked Won’t play. A shelf with nothing honest to show is hidden rather than padded — a brand-new account with no favourites yet will see fewer shelves until it has something to go on.
- Each Discover shelf is **one row you scroll sideways**, not a wrapping grid. Park the pointer at either end (or click the **arrows**) to ease the row; drag or wheel the **slider under the covers** to pan, or shift-wheel / swipe sideways over the tiles. A vertical mouse wheel over the tiles themselves still scrolls the **page**, so a row never traps vertical scroll. The tile-size slider in the bar resizes Discover tiles as well as Library ones.
- **A Discover shelf with nothing in it is not shown.** Rows the server generates — Continue playing, Friends playing, the charts — are dropped when they have nothing, rather than rendering a heading over empty space, and the slot goes to a row that does have something. A shelf an admin curated is the exception: it stays visible even when empty, so whoever built it can see that it is empty. On a row's own page, **Load more** says how many are left ("Load more (28 left)") whenever the server could count the row; on a very deep row it just says **Load more**, because claiming a number it did not reach would be a guess.
- **Discover is split into zones.** A strip above the feed offers the named surfaces this install actually has — **For you** (what you play, and what people you know play), **New & updated**, **Popular here**, **Elsewhere** (news, deals, extras) and **Curated** (shelves someone here built by hand). Each opens at `/discover/zone/<name>` showing only its own shelves. The full feed stays underneath the strip, so ignoring zones costs you nothing. A zone only appears when it has shelves with something in them, and a shelf you hide leaves its zone too — a zone is a view of the same feed, not a second copy of it.
- **See all** on a shelf opens that row’s full page. The **News** shelf’s See all opens `/news`. A genre zone’s See all opens a **genre hub** (`/discover/hub/genre/…`) with unplayed / newly added / loved shelves.
- Every tile in every row is the **same size**, news tiles included — a headline with no artwork no longer makes a shorter tile than the one beside it, and rows line up with each other down the page. A hovered tile grows without being clipped by the row above or below it.
- Row headings carry an accent mark rather than a rule across the page.
- **Pin a shelf** with the pin button on its heading to keep it at the top of Discover, and **Hide** to take it off your feed entirely. Both take effect as soon as you click (they also save to your account). They appear on the heading when you hover the row.
- **Rows** in the bar is where you undo either: it lists every shelf your feed can show — hidden ones included — with **Show** to bring one back, and **↑ / ↓** to put your pinned shelves in the order you want them. Pins and hidden rows are stored **on your account**, so they follow you to the TV and the phone. Hiding only changes *your* feed; it never affects anyone else. A shelf an admin has pinned for everyone cannot be hidden.
- **Favorites** (`/favorites`) is a library too: it carries the same **Filters** button beside the rail toggle, the same All / Games / Soft titles / Emulators / Utilities strip, and the same pager at the foot of the grid — so a large favourites collection can be narrowed by title or kind instead of only scrolled.
- **Collections**, **Wishlist**, **Updates**, **Ownership**, **Big Picture**, **Ways to Play**, optional **VR** / **Trailers** / **Calendar** — under primary nav or **More**.
- **Ownership** (`/ownership`) is a **register**, not a store client. Steam, GOG, Epic and Amazon Games can **live-sync** owned IDs and names when a token is saved (GOG Galaxy refresh token, Epic device-auth JSON, Amazon Nile/Heroic user.json; unofficial surfaces, honest 401). CSV still works. Oneirodex never downloads DRM titles.
- **Updates** (`/updates`) leads with the **freshness inbox** — the titles that look behind — across the full width, with **Search stores** and an **Upcoming releases** teaser paired beneath it. One refresh control, not two: the glyph on the inbox heading runs a real probe against store versions and re-reads the list when it finishes.
- **Release calendar** (`/calendar`): **today** is ringed, a day carrying more than one release says how many, and picking a day opens its titles **beside** the month rather than under it on a wide screen — so the grid never moves when you click. A busy day's list scrolls inside its own panel instead of setting the page height.
- **Adding to a collection** no longer means opening the shelf first: **Add to collection…** is on the tile menu in any grid, and on the game's details page. Pick a shelf and it is filed.
- **Admin** is not a primary TopNav button beside Favorites — admins reach `/admin/dashboard` from the section **context** strip (and Ctrl+K → Admin).
- **Trailers** empty library returns HTTP 200 with a CTA (not an error) — open a title with trailer metadata or ask an admin to enrich covers/videos.

Game details (`/game_details/<uuid>`) is a full member SPA page under the same TopNav. Where a
title has wide, title-free key art (`hero` / `fanart`, else its first screenshot) that art sits
**behind the page** — blurred, desaturated and faded out well above the content, so it is
atmosphere rather than a picture the text is sitting on. The **cover is never used** for this: a
cover carries the title, and the title is already on the page in readable type. A title with no
wide art keeps the flat surface. Breadcrumb is **Game Catalog** (or **Systems** on a console leaf) › primary genre › title. Every taxonomy chip — genre, theme, mode, perspective — and the genre crumb open the **catalog filtered to that value**, so they answer "what else do I have like this" with the complete list. (Genre used to divert to the curated genre hub; that hub is still what a Discover genre zone's See all opens.) When trailers or screenshots exist, a compact **media stage** (primary trailer or first shot + thumbs) sits beside the summary and is the page's only gallery — clicking the still opens the screenshot lightbox, and a trailer uses the player's own fullscreen; embeds do not autoplay under reduced motion. **About** renders `storyline` when present. **System requirements** and **Store languages** appear only when Steam fill-only `store_specs` exists (never invented for ROM-only titles; ROM peel chips stay filename truth). **More from** this developer or publisher is other vault titles (ACL, hidden when fewer than two others). The page also carries: cover, **summary + details in a two-column layout** on wide viewports — with media present the two stack to the left of the stage and later sections (versions, extras) run full width below; without media the later sections **sit beside the facts rail** rather than starting below it (summary auto-wraps with Show more; narrow viewports still read summary → details → the rest), **versions** (Default chip · measured size · **Download on updates only** — the base game's download is the primary action at the top of the page, so the versions list offers it only per update, for when you already have the game and just need one patch · hide Download + **Missing on disk** when `path_missing` / not downloadable; librarians/admins **Remove missing versions** for orphan cleanup — base-only default, no full GameVersion schema yet), **Extras & DLC** panel (from details `extras[]` — each row shows honest **on-server** when known; versions fallback only if the `extras` key is absent). Screenshots and trailers live **only** in the media stage — there is no second gallery at the foot of the page. A shot appears **only when it actually loads**: art that was never downloaded is not listed, and a shot that fails in the browser drops out of the stage, so the thumbs are either real screenshots or nothing. Trailers come from structured `trailers[].embed_url` (or `video_urls`); a **YouTube demo** link via `youtube_demo_url` shows instead when there is no embed. Also **brand store/catalog link marks**, Play / companion Install actions, **Add to collection…**, store links, then **Launch Steam** and **Check updates & DLC** as the last two — the row reads play → where else this exists → launch it there → go and look for changes, rather than putting a second "start the game" button beside the first. Also ROM language chips, Social companion dock, and Translations & patches when needed. **Admins** get a **⋮** menu on the **cover tile** (Edit Details / Edit Images / Open path) — same Library card chrome — plus path rows under Details from `full_disk_path` / `server_path`. **Open path** opens **OpenPathModal** — queues companion `open_path` (clipboard fallback when offline or queue fails); it does **not** jump to Auto Scan.

**Details media (Wave 2a shipped):** `GET /api/games/<uuid>/details` includes `video_urls` (parsed list), structured `trailers[]` (`url` · `embed_url` · `provider`), `has_trailers`, `screenshot_count` + honest `screenshots[]`, optional `youtube_demo_url` when no trailer videos, and `extras[]` (`type` dlc/extra/manual/translation_patch · `name` · `on_server` · `uuid`). **Admins only** also receive `full_disk_path` / `server_path`. **PC libraries** associate common `DLC`/`extras` under-game folders (+ sibling `Title DLC` sidecars) on scan — **console/ROM DLC ingest stays deferred** (GM-locked). Extras without a disk presence show `on_server: false` — the UI does not pretend they are on the vault.

**Store / catalog marks (shipped):** Steam · GOG · Epic · PlayStation · Xbox · Amazon/Prime Gaming · Humble · itch.io · EA · Ubisoft · Fandom/Wikia · IGDB · YouTube · Wikipedia · official site · common socials · unknown fallback mark. Icons are **theme-adaptive** (light/dark aurora): PNG silhouettes use CSS `mask-image` + `currentColor` / `--od-text`; SVG path brands use `fill="currentColor"`. Chip border/hover keeps a brand accent (`--od-store-color`); Ubisoft is an inline SVG (supplied PNG was solid black / unusable).

**Logo gap:** none for the former human-asset list (itch · Humble · EA · Ubisoft · Xbox · PSN · Amazon · wikia/fandom · unknown). Remaining unmatched store types still open with the unknown mark + plain label.

## Related media

Above the screenshots, a game can carry the **media connected to it** —
adaptations, tie-ins, novelisations, documentaries, and soundtracks. Click any
card for a popup with the detail and a link out to where that thing legitimately
lives.

- Kinds: film · TV series · anime · book · comic · soundtrack/music · podcast.
- Relations: adaptation · tie-in · soundtrack · novelisation · documentary ·
  inspired by.
- Only the kinds actually present are shown — you never get a row of empty
  categories, and a game with no related media shows **no section at all**.
- Librarians and admins add entries; every member can read them.

**This is context, not a tracker.** There is deliberately nothing to mark
watched, rate, or progress — those fields do not exist on the model. Links must
point at a store or streaming page; anything download-shaped is refused outright.

API: `GET`/`POST /api/games/<uuid>/related_media` ·
`DELETE /api/games/<uuid>/related_media/<id>`.
