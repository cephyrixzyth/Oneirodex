# Alembic baseline notes (wave A3.1)

> **Doc status:** Reference

The first revision, `b9ab856b09ff_baseline_schema_squash_of_updateschema_.py`,
is a **squash** of the schema that `db.create_all()` + `oneirodex/updateschema.py`
built up before Alembic existed. It was autogenerated against an empty database
(so it is ~all `op.create_table` / `op.create_index`) and then hand-extended
with the objects `updateschema.py` created that the models never declared.

> Since wave A2.2 the models are a package (`oneirodex/models/`, split by
> domain) rather than a single `oneirodex/models.py`. References to `models.py`
> below are historical; `target_metadata` in `alembic/env.py` is still
> `db.metadata` and importing `oneirodex.models` still registers every table.

## How the baseline was produced

1. `alembic revision --autogenerate` against a fresh empty Postgres DB, with
   `oneirodex.models` `db.metadata` as target metadata → 75 `create_table`s
   plus every model-declared index/constraint.
2. Hand-appended the "squashed from `oneirodex/updateschema.py`" block in
   `upgrade()` (with mirrored drops in `downgrade()`), covering the indexes
   listed below.
3. Verified: a fresh `alembic upgrade head` produces a schema byte-identical
   (via `pg_dump --schema-only`) to `create_all()` + `updateschema.py`, apart
   from the `alembic_version` bookkeeping table.

## `alembic check` allow-list

`alembic check` is **clean** (`No new upgrade operations detected`). It is kept
clean by a named allow-list in `alembic/env.py` (`_BASELINE_ONLY_INDEXES` /
`_include_object`): indexes the baseline creates but `models.py` does not
declare, so autogenerate would otherwise propose dropping them on every run.

| `ix_duplicate_fix_logs_matched_game` | `duplicate_fix_logs` | admin triage log |

The `unique_game_*_image` partials enforce "one primary artwork of each kind per
game" (screenshots stay multi). They are functionally important, not cosmetic —
which is why they live in the baseline rather than being dropped.

### Retiring an entry

When an index here is promoted into its model's `__table_args__`, delete it from
`_BASELINE_ONLY_INDEXES` in `alembic/env.py` **and** from this table in the same
change, and add the matching `op.create_index` to the new revision (not the
baseline).

## Real diffs fixed rather than excluded

- `newsletters.recipients` was `sqlalchemy.dialects.sqlite.JSON` in `models.py`
  (a stray SQLite dialect type in a Postgres-only app). Changed to `db.JSON`;
  the on-disk column was already plain `json`, so no data migration.
- `user_preferences.items_per_page` had a Python-side `default=50` but no
  server default; `updateschema.py` set `DEFAULT 50` on the column. `models.py`
  now also carries `server_default='50'` and the baseline sets it, so
  `compare_server_default` is satisfied.
- `JSONEncodedDict` (TypeDecorator over `TEXT`) is rendered as `sa.Text()` in
  revisions via `render_item` in `env.py`, so migrations don't import the app
  package.
