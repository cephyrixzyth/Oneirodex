## Incident 2026-09-17 — a commit reached `main` without a PR

`e6d5b4a4` (three Discover notes: article-row scroll lane, grab-to-scroll, Steam art fallback) was committed and pushed straight to `main`. Cause: a background job ("merge #124 then wait for #125/#126") ran `git checkout main` on this **shared** checkout while the foreground was mid-commit on `v1/discover-upcoming`, so the amend landed on `main` and `git push` went to `origin/main`. The change had passed every local gate (vitest 42 + 14, pytest 20, prettier, eslint, both JS ratchets), CI runs on `main` pushes and was queued immediately, and no force-push was used to hide it. If that run is red the commit is reverted through a PR.

**Rule from this:** on the shared checkout, **a background job never runs `git checkout`, `git switch` or `git pull`.** Merge/wait jobs poll and report; branch moves happen in the foreground only, immediately before the commit they serve. Same lesson as `43d95f15` in the 2026-09-02 session board, relearned.
